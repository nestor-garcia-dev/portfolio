# Portfolio publishing rules

This repository is public-facing. Keep content factual, concise, and useful to someone evaluating Nestor Garcia's engineering work.

- Working plans, career strategy, unpublished drafts, and publication checklists belong in the separate sibling `portfolio-planning` repository, which must remain private.
- Do not copy application source, customer records, logs, credentials, or production exports into this repository.
- Feature a project only when its write-up explains implemented behavior and has working exploration links.
- Use `templates/project-writeup.md` for new projects. Keep detailed content in the project's own repository; this repository is the index.
- Use Dinaryo as the public product name. Ledgerly is an internal identifier.
- Dinaryo reconciles money; it does not process payments. Business volumes are approximate and business-reported, not product revenue.
- No invented performance, uptime, customer, defect, or adoption claims.
- Preserve the user's professional experience alongside independent projects.
- Do not publish a job level (Senior, Staff, Principal, and similar). Describe the work and ownership so the copy stays accurate if the title changes. Do not state a years-of-experience count; it goes stale.
- Before publication, review the exact staged files and their history. Git ignore rules do not make tracked content private.
